# floodfusion v1.2 — decisions and deviations log

The v1.2 protocol (`reports/protocol_v1_2.md`) is written at the freeze. Until then this log records, **before the
result it could affect exists**, every rule, decision and disclosure that bears on v1.2's claims. Dates are UTC; one
row per line.

## Rules fixed before any v1.2 result

| Date (UTC) | Rule | Reason |
|---|---|---|
| 2026-10-13 | Only the prospective blind test (CEMS codes ≥ EMSR899, scored after the freeze) is confirmatory; everything else in v1.2 is exploratory. | The CEMS 2023–26 benchmark has been seen, and public training sets (GEOID-Flood, ImpactMesh) now cover its activations. |
| 2026-10-13 | Model selection uses cross-validation only, with tuning on an inner split of fold 0's training groups (`assign_group_folds(train_records, 4)`). | `k_fold_groups` validates fold *i* on fold *i*+1's test groups, so tuning on that validation split would select on test groups. |
| 2026-10-13 | Equal tuning budget: at most three learning rates per model family (row 20, TerraMind-fair). | Fairness of the TerraMind comparison. |
| 2026-10-13 | TerraMind-fair size and adaptation: TerraMind-base with LoRA, unless a one-epoch probe projects more than 3 h per pooled cross-validation run; then TerraMind-base frozen, then TerraMind-small with LoRA. | GPU budget (8 GB laptop GPU, ~40–60 GPU-hours for all of v1.2), fixed before any TerraMind-fair result. |
| 2026-10-13 | If the largest 100 km group of the pooled Kuro Siwo + GEOID-Flood set holds more than 25 % of its windows, cross-validation uses buffered spatial blocks instead of groups. | A single giant group would leave folds unbalanced. |
| 2026-10-13 | GFM is a comparator, never a model input. A unit counts for a GFM comparison only if GFM covers ≥ 95 % of its scored pixels. | GFM changes its members in 2027; missing GFM pixels would otherwise count as misses. |
| 2026-10-13 | The CEMS 2023–26 benchmark is scored with v1.2 models once, after the freeze tag. | Prevents choices made after seeing it. |

| 2026-10-13 | Blind-test stopping rule raised to 20 activations in 15 clusters (or 2027-12-31), from 10 in 8. | Power, before any blind flood was looked at: with v1.1's per-activation SD of the paired IoU gap (0.077 for P4, 0.071 for P3), an exact sign-flip test at Holm's smallest level (0.05/3) detects about 0.10 IoU at 80 % power with 10 activations, about 0.06 with 20 (simulation, 1 500 draws). The v1.2 differences expected (ours vs a fairly trained TerraMind) are smaller than 0.10. |
| 2026-10-13 | The TerraMind-fair probe, made exact (`scripts/tm_probe.py`): 20 timed training micro-batches (after 5 warm-up) of each variant and of row 9, bf16, on the same Kuro Siwo chips. A pooled CV run is projected as row 9's mean v1.1 Kuro Siwo run (972 s) × pooled training chips / 3 178 × the variant's time per batch / row 9's. A variant must also peak at ≤ 7.5 GB. If none is under 3 h, the last that fits in memory (TerraMind-small + LoRA) is used. | A full epoch of each variant would cost hours; the per-batch ratio is what the 3 h rule needs. Recorded before the probe ran. |
| 2026-10-13 | The TerraMind-fair probe, corrected after code review and before it ran: 32 timed micro-batches after 8 warm-up (whole optimizer steps), the training loop's own step (modality dropout, gradient accumulation of 4, clipping, the project optimizer, channels_last), on one seeded sample of chips shared by every model. The 7.5 GB cap applies to peak **reserved** memory. If no variant fits, there is no fair opponent and the CV stage does not start. | The first version stepped the optimizer on every micro-batch, which overcounts the cost of row 9 (all parameters trained) against LoRA/frozen TerraMind and would have biased the 3 h projection in TerraMind's favour. Reserved memory is what an out-of-memory error depends on. |
| 2026-10-13 | The two candidate inference add-ons, defined before any pooled-CV run: (1) per-scene self-calibration = the bounded EM prior shift (\|Δlogit\| ≤ 2) of the CEMS scorer, fitted on the scene's own unlabelled scores, with the run's deployment prior π0; (2) HAND gate = the baselines' hard cut, no flood where HAND ≥ 15 m. The planned hysteresis and per-component water-surface check are dropped. Each is scored on whole CV test stacks (a 5.12 km square is the scene); IoU is pooled per split group, then averaged over groups. An add-on is adopted if it raises that mean by ≥ 0.005 **and** raises the IoU of more than half of the groups, judged on the selected model's CV runs. If both qualify, both are adopted. | The protocol names both add-ons but not their exact operators. The cut is the simplest HAND rule already validated in this project (the physics baselines); a component-level rule would add choices that CV would then have to make. |
| 2026-10-13 | The selection measure, made exact before any pooled-CV run: "pooled-CV macro IoU at τ*" is the plain arm of `floodfusion.cv_addons`: every test stack of the five CV runs predicted whole (the deployment operator), confusion counts pooled per split group, IoU averaged over groups. Candidates are compared simplest first (row 9, then row 21); a candidate is chosen over row 9 only if it beats it by more than 0.005. The add-ons are judged on the chosen row's runs. Finals: all groups × seeds 42–44 for the chosen row and the fair TerraMind. | Chip-level CV metrics average over chips, not groups, and do not use the stack-level operator the blind test uses. |
